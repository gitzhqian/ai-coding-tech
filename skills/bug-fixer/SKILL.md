# Personal Guide Bug Fixer

你正在维护 Personal Guide 项目。

本 Skill 的目标不是“看到错误就立即修改代码”，而是按照
“复现 → 定位 → 分析 → 最小修复 → 验证”的流程处理故障。

## 1. 先理解问题

收到 Bug 修复任务后：

1. 明确用户描述的现象。
2. 判断问题属于哪一类：
   - Flask 应用启动问题
   - Python 代码错误
   - 页面或模板错误
   - 用户输入与表单处理错误
   - 行程生成逻辑错误
   - Qwen API 调用错误
   - 本地景点数据读取错误
   - 前后端交互错误
   - 环境或依赖错误
3. 不要在尚未确认问题原因时大范围修改代码。

## 2. 复现问题

优先尝试复现用户报告的问题。

检查：

- 当前运行目录是否为 personal-guide
- Python 环境是否正确
- Flask 应用是否能够启动
- Terminal 是否存在 Traceback 或错误信息
- 页面是否能够正常访问
- 用户操作是否能够稳定触发问题

如果问题无法复现，应先说明当前观察结果，再继续分析。

## 3. 收集上下文

根据问题类型读取必要文件。

优先检查：

- app.py
- utils/
- utils/guide.py
- utils/ai_client.py
- utils/planner.py
- templates/
- data/attractions.json
- requirements.txt
- .env.example

只有在确实需要时才读取其他文件。

不要读取或输出真实 API Key。

## 4. 分析根因

修改代码之前，先根据以下信息判断根因：

- Python Traceback
- Flask 日志
- HTTP 状态码
- Qwen API 返回错误
- Terminal 输出
- 输入参数
- 调用链
- 最近修改过的文件

需要区分：

“错误发生在哪里”

和

“真正原因在哪里”。

不要只修复表面错误。

## 5. Qwen API 问题专项检查

如果问题涉及大模型调用，依次检查：

1. QWEN_API_KEY 是否存在。
2. QWEN_BASE_URL 是否正确。
3. QWEN_MODEL 是否正确。
4. 环境变量是否成功加载。
5. 请求参数是否符合当前接口要求。
6. 网络和代理配置是否影响访问。
7. API 异常是否被正确捕获。
8. fallback / 本地降级逻辑是否正常。

禁止：

- 将 API Key 写入源码。
- 在日志或回答中显示完整 API Key。
- 为了消除报错而删除异常处理。
- 在 API 失败时伪造“调用成功”。

## 6. 制定最小修复方案

找到根因后：

1. 说明问题原因。
2. 说明准备修改哪些文件。
3. 优先进行最小范围修改。
4. 不重构与当前 Bug 无关的代码。
5. 保留当前已经正常工作的功能。
6. 如果存在多个方案，优先选择风险最低、改动最小的方案。

## 7. 执行修复

修改代码时：

- 遵循项目现有代码结构。
- 尽量复用已有函数。
- 不重复创建已有模块。
- 不随意修改 API 接口。
- 不修改与 Bug 无关的页面布局。
- 不删除已有 fallback 机制。
- 不修改 .env 中的真实密钥。

如果修改可能影响多个功能，应先说明影响范围。

## 8. 修复后验证

修改完成后必须进行验证。
